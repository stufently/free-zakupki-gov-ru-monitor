# Changelog

## 0.2.2 — 2026-07-29

Починены иконки расширения, автоматизирована выкладка в Store.

### Исправлено

- **Иконки расширения были чёрно-белые.** В `extension/icons/` лежали 16-битные greyscale PNG — чёрный квадрат с белым колокольчиком, не имевший ничего общего с синим `icon.svg` (градиент, колокольчик, знак рубля). Их когда-то положили руками и ни разу не собрали из SVG, поэтому расхождение никто не замечал: в браузере иконка маленькая, а `icon128.png` идёт главной картинкой карточки в Chrome Web Store — то есть публиковать собирались именно чёрно-белую заглушку. Теперь PNG собираются из SVG скриптом `scripts/make-icons.cjs`.
- В манифест добавлен размер **32** — Chrome рекомендует набор 16/32/48/128, без 32 система масштабирует 16 или 48 и иконка на панели выглядит замыленной.

### Добавлено

- Marquee-плитка 1400×560 — второй промо-ассет Store, нужный для витринных мест. `scripts/make-promo-tile.cjs` теперь собирает обе плитки одним прогоном, чтобы они не разъезжались по стилю.
- Отдельная иконка карточки `docs/screenshots/store/store-icon-128.png` — рисунок 96×96 в холсте 128×128. Google просит для квадратной иконки именно такие поля: в витрине иконки выравниваются по визуальному весу, и full-bleed квадрат выглядит крупнее соседних. Иконке расширения поля не нужны, поэтому это отдельный файл, а не копия.
- Всё, что просит форма Store, теперь лежит в одной папке и целиком пересобирается скриптами — ручных копий не осталось.

### Инфраструктура

- Выкладка новой версии в Chrome Web Store автоматизирована: после bump'а версии workflow не только публикует GitHub Release, но и заливает ZIP в Store с отправкой на ревью. Логика в `scripts/cws-deploy.sh` — отдельным скриптом, чтобы то же самое можно было запустить руками, когда CI недоступен. Пока секреты не заданы, шаг печатает `notice` и завершается успешно: до появления аккаунта разработчика релизы не должны краснеть.
- Взят **Chrome Web Store API v2**, а не v1. V1 (`/chromewebstore/v1.1/`) объявлен устаревшим и поддерживается только до 15 октября 2026 года — на нём написано большинство готовых GitHub Actions для Store, и после этой даты они перестанут работать.
- `tests/cws-deploy.test.mjs` — скрипт выкладки проверяется против локального мока Store, 31 проверка. Настоящий Store в тестах недоступен и не должен быть: у него один боевой товар, и «проверить выкладку» означало бы выложить. Без мока скрипт впервые исполнился бы только на живом релизе, а ломается он тихо — сборка зелёная, версия в Store старая. Закрыты асинхронная обработка пакета, отличие отказа от таймаута и от HTTP-ошибки, протухший токен и режимы `upload-only` / `publish-only`.
- Ручной запуск умеет три режима. `publish-only` нужен не для удобства: если пакет уже принят, а публикация упала, повторная загрузка той же версии отклоняется как неувеличенная — и повторить выкладку было бы нечем, кроме bump'а версии на пустом месте.
- Промо-плитка 440×280 (`scripts/make-promo-tile.cjs`) — последний недостающий ассет Store. Без неё расширение не попадает в подборки.
- В описание для Store добавлена оговорка, что расширение неофициальное и с оператором ЕИС не связано. Название содержит домен госпортала, а правила Store запрещают вводить в заблуждение о принадлежности — оговорка стоит первой строкой, а не в конце.
- Инструкция для ревьюера (Test instructions). Ревьюер почти наверняка вне России: портал ему не откроется, сертификат Минцифры Chrome не доверяет, и без пояснения расширение выглядит сломанным.
- Проверено, что в Store уходит именно ZIP из релиза: `manifest.json` в корне архива, тестов и документации внутри нет, распакованная сборка v0.2.1 поднимается в Chromium.

## 0.2.1 — 2026-07-29

Проверка расширения в браузере, материалы для публикации и одно изменение
поведения сети.

### Изменено

- Адрес ленты проверяется до запроса и ещё раз после ответа: только `https` и только `zakupki.gov.ru` с поддоменами. Вторая проверка нужна из-за переадресации — переходы выполняет сам браузер, и `redirect: "follow"` увёл бы запрос с портала мимо первой проверки. `host_permissions` такой гарантии не давали — они ограничивают чтение ответа, но не мешают запросу уйти, поэтому произвольная ссылка из настроек превращалась в обращение к стороннему сайту. Теперь чужой адрес не сохраняется в настройках и не запрашивается, а в статусе ленты видно понятную причину вместо невнятного сетевого сбоя.
- В адресе ленты запрещены логин с паролем и нестандартный порт: в RSS портала их не бывает, а `https://zakupki.gov.ru@evil.com` — типичный приём маскировки чужого хоста под нужный.
- Якорь (`#...`) больше не влияет на ключ ленты. На сервер он не уходит и содержимое не меняет, но два адреса, различающиеся только якорем, считались разными лентами — с удвоенными уведомлениями об одних и тех же закупках.
- Описание закупки (`description`) больше не сохраняется. Оно не показывается ни в popup, ни в уведомлении, но было самым объёмным полем записи: расширение хранило содержимое страниц портала без всякой цели.
- Запрос ленты уходит с явным `credentials: "omit"` — cookie портала не
  отправляются, даже если пользователь на нём авторизован. Лента публичная,
  cookie для неё не нужны, а фоновая проверка идёт каждые несколько минут.
  Раньше режим не задавался и зависел от поведения браузера по умолчанию:
  спецификация даёт `same-origin` (то есть без cookie при кросс-ориджин), но
  расширения с `host_permissions` — отдельный случай, и полагаться на неявное
  поведение в том, что касается чужих cookie, не стоит.

### Добавлено

- `tests/ui-live.cjs` — проверка интерфейса и побочных эффектов в настоящем браузере на живых данных: уведомления действительно создаются и их id — ссылка на закупку, badge показывает счётчик и краснеет с «!» на сломанной ленте, `chrome.alarms` заводится и перепланируется при смене интервала, кнопки настроек и popup делают то, что написано. 24 проверки. До этого ни уведомления, ни badge, ни расписание в браузере не проверялись — а уведомления это основная функция расширения.
- Скриншоты в README — сняты с работающего расширения на живых данных портала, а не нарисованы: popup с найденными закупками, настройки со статусом лент и вид при сбое с подсказкой про сертификат. Пересобираются скриптом `scripts/make-screenshots.cjs`.
- `check-sw` проваливает сборку, если из service worker'а пропадут `credentials: "omit"` или проверка домена: обе строки легко потерять при рефакторинге, и потеря была бы тихой — расширение продолжило бы работать, просто начав слать cookie или ходить на чужой хост. Плюс 12 юнит-тестов на сам фильтр адресов, включая `zakupki.gov.ru.evil.com` и `http://`.
- `tests/e2e-live.cjs` больше не требует `totalNew === 0` на повторной проверке. Лента живая: по запросу «охрана» новые лоты появляются за секунды между прогонами, и строгий ноль давал ложные падения. Признак работающей дедупликации другой — известные записи не приходят повторно: прирост `seenIds` равен `totalNew`, а не всему фиду.
- `docs/privacy-policy.md` — политика конфиденциальности. Форма Chrome Web Store требует URL, и раздела в README для неё мало: нужен отдельный документ с датой, перечнем хранимых данных, обоснованием каждого разрешения и порядком удаления.
- `docs/chrome-web-store.md` — тексты карточки Chrome Web Store, обоснования каждого разрешения для ревью, ответы формы Data Usage и чек-лист. Скриншоты подогнаны под требование Store (ровно 1280×800) в `docs/screenshots/store/`.

- Парсер проверен на **живой ленте ЕИС** (снята 29.07.2026): 200 записей разобраны за 20 мс, все с уникальными id, абсолютными ссылками и корректными датами, без остаточных тегов и entity в описаниях. Обрезанная до 5 записей лента добавлена фикстурой `tests/fixtures/real-eis-rss.xml`, тестов стало 44.
- `tests/e2e-live.cjs` — проверка против живого портала: расширение в настоящем Chromium проходит весь путь (fetch из service worker → offscreen → storage) и на повторной проверке даёт `totalNew: 0`. Прогон 29.07.2026: 200 записей скачаны и разобраны, уведомлений на первом запуске нет, дублей на втором нет. В GitHub CI не включён — zakupki.gov.ru доступен только из РФ.
- Зафиксировано тестом, что в лентах ЕИС **нет `<guid>`** — идентичность записи держится на `<link>` с `regNumber`. Если этот fallback сломать, дедупликация начнёт слать дубли уведомлений.

## 0.2.0 — 2026-07-29

Расширение версии 0.1.0 не работало ни у кого: разбор лент падал на каждой проверке.
Этот релиз чинит причину и делает будущие сбои видимыми.

### Исправлено

- **Критично: парсер падал на каждой проверке ленты.** `rss.js` вызывал `DOMParser`, которого не существует в service worker MV3 — ни в одной версии Chrome. Каждая проверка завершалась `ReferenceError`, ошибка гасилась общим `catch`, и пользователь видел «новых записей нет». Разбор XML перенесён в offscreen-документ (`chrome.offscreen`, причина `DOM_PARSER`), сеть осталась в service worker'е. Причину нашёл [@doovoos](https://github.com/doovoos) в PR #1.
- Ответ, не являющийся RSS/Atom, больше не считается пустой лентой. HTML-заглушка портала и XML с чужим корнем раньше давали `items = []`, лента молча помечалась инициализированной, и уведомления не приходили уже никогда. HTML распознаётся по сырому тексту до разбора: настоящая HTML5-страница невалидна как XML и иначе давала бы бесполезное «Невалидный XML».
- Наличие offscreen-документа проверяется через `chrome.runtime.getContexts()` (Chrome 116+), а не через `chrome.offscreen.hasDocument()` (Chrome 150+). При заявленном минимуме Chrome 119 второй вариант — `undefined` и `TypeError` на каждой проверке, то есть тот же класс отказа, что и в 0.1.0.
- Таймаут запроса покрывает и чтение тела ответа. Ранее таймер снимался сразу после получения заголовков, поэтому бесконечное тело вешало всю очередь проверок: `checkAllFeeds` сериализован через `inFlight`.
- Лимит размера считается в байтах через `arrayBuffer()`, а не в символах строки — кириллица в UTF-8 занимает два байта на символ. Кодировка берётся из `charset` в `Content-Type`.
- Повтор разбора принудительно закрывает offscreen-документ перед пересозданием: зависший документ числился живым и переиспользовался.
- Записи ищутся только среди прямых потомков `channel`/`feed`. `getElementsByTagName` обходит всё поддерево, поэтому `<item>`, вложенный в содержимое другой записи, становился отдельной записью.
- Сетевые сбои размечаются классом `NetworkError` на границе `fetch`, а не проверкой `instanceof TypeError` в общем обработчике — иначе любой внутренний `TypeError` выдавался бы за проблему с сертификатом.
- Badge пересчитывается service worker'ом по сообщению `refreshBadge`. Кнопка «Очистить» стирала его напрямую, из-за чего пропадал индикатор сломанной ленты.
- Относительные `<link>` разворачиваются в абсолютные относительно URL ленты — раньше такая запись не открывалась по клику.
- В RSS-ленте разбираются только `<item>`, в Atom — только `<entry>`. Раньше обе ветки выполнялись всегда и могли давать фантомные записи.
- Заголовок канала берётся из прямого потомка `channel`/`feed`. Раньше брался первый `<title>` во всём документе, то есть на пустом канале — заголовок первой записи.
- Сбой показа уведомления больше не помечает ленту сломанной: записи уже сохранены и видны в popup.
- `_locales` подключены по-настоящему — `name` и `description` в манифесте берутся через `__MSG_`. Раньше файл локали лежал мёртвым грузом.

### Добавлено

- Диагностика по каждой ленте: время последней попытки, время последнего успеха, число записей в ленте и текст ошибки. Видна под лентой в настройках и красной строкой в popup, badge при сбое краснеет.
- Подсказка про TLS-сертификат НУЦ Минцифры: с 4 июля 2026 года zakupki.gov.ru работает на нём, а Chrome, Edge и Brave ему по умолчанию не доверяют. Формулировка намеренно вероятностная — `fetch` отдаёт неотличимую ошибку на DNS, offline, блокировку и TLS.
- Таймаут запроса 30 секунд и отбраковка ответов больше 5 МБ: зависшая лента больше не блокирует очередь остальных.
- `tests/check-sw.mjs` — гард, проваливающий CI при возврате DOM API в service worker, пропаже offscreen-документа, битой ссылке `__MSG_` или вызове API новее, чем `minimum_chrome_version`.
- `tests/smoke-chrome.cjs` — смоук-тест в настоящем Chromium: грузит распакованное расширение и прогоняет боевой путь через offscreen. Юнит-тесты идут с полифилом `@xmldom/xmldom` и по построению не могли поймать отказ 0.1.0.
- Поддержка RSS 1.0 (RDF), где `<item>` лежат рядом с `<channel>`, а не внутри него.
- Фикстуры и проверки на относительные ссылки, HTML вместо RSS (валидный и настоящий невалидный), чужой корень XML, пустую валидную ленту, посторонний `<entry>`, вложенный `<item>` и RDF-ленту. Тестов стало 36 против 14.

### Инфраструктура

- `actions/setup-node@v6` → `@v7`, `softprops/action-gh-release@v2` → `@v3`, Node 20 (EOL) → 24 LTS, `npm install` → `npm ci` с кешем.
- Релиз выпускается автоматически по bump'у `version` в манифесте: мержа в `main` достаточно, workflow сам создаёт тег `vX.Y.Z` и публикует Release. Ручной шаг с тегом был местом, где выпуск забывали. Если тег на текущую версию уже есть, публикация пропускается, поэтому обычные коммиты релизы не плодят.

### Осталось на 0.3.0

Группировка записей по лентам, кнопки сброса ленты и показ последних записей при первом запуске — из PR #1, вынесено отдельно как UX-изменения.

## 0.1.0 — 2026-05-01

Первый публичный релиз.

- Chrome MV3 расширение для мониторинга RSS-лент zakupki.gov.ru
- Service worker с `chrome.alarms` для периодической проверки
- Настройки: список лент (CRUD), кастомный интервал в минутах (1 минута – 7 дней, по умолчанию 10 минут) + presets
- Уведомления через `chrome.notifications`, клик открывает страницу закупки
- Badge text с количеством непрочитанных записей
- Popup со списком последних найденных записей
- Локальное хранилище (`chrome.storage.local`), без внешних запросов кроме fetch RSS
- Парсер RSS 2.0 и Atom без зависимостей, namespace-aware (поддержка dc:date)
- inFlight guard на concurrent проверки + троттлинг 1.5 сек между фидами
- Дедупликация лент по canonical URL
- Явный флаг `initialized` для корректного first-run при пустых фидах
- GitHub Actions: автоматическая сборка ZIP и публикация в Releases по тегу `v*`
- Fixture-тесты на парсер (14 assertions)
