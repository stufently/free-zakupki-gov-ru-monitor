## Запланировано

### 0.3.0 — UX из PR #1

Разобрать [PR #1](https://github.com/stufently/free-zakupki-gov-ru-monitor/pull/1) от @doovoos по частям, каждую с тестами:

- группировка записей по лентам в popup со сворачиванием;
- кнопки «Сбросить ленту» и «Сбросить все ленты»;
- показ последних 10 записей при первом запуске ленты, без уведомлений;
- дедупликация `recent`. Ключом брать `feedKey + item.id`, а не один `link`: по `link` схлопнутся находки одной закупки из разных лент.

### 0.3.x — надёжность

- Повторы с backoff при сетевых сбоях.
- `ETag` / `If-Modified-Since`, чтобы не тянуть неизменившийся фид.
- Гонять `tests/e2e-live.cjs` перед каждым релизом: нужен доступ к zakupki.gov.ru из РФ (прокси).
- Клик по системному уведомлению (`chrome.notifications.onClicked` → открытие вкладки) — единственный сценарий, который не автоматизируется: событие порождает сам браузер. Проверено косвенно: id уведомления равен ссылке на закупку.
- Проверка на самой старой поддерживаемой версии Chrome (119). Смоук-тест гоняется на текущем Chromium, где доступны и `getContexts`, и `hasDocument`; несовместимость с 119–149 поймал бы только запуск на старом билде.
- Различать ленты в уведомлениях. `channel/title` у ЕИС — «Результаты поиска в реестре заказов и закупок» для ЛЮБОГО поиска, поэтому fallback `feed.title || parsed.channelTitle` даёт одинаковую подпись всем безымянным лентам. Подставлять в неё `searchString` из URL ленты либо требовать название при добавлении.
