### Проверить автовыкладку на следующем обновлении

Цепочка CI → Store ни разу не исполнялась на живом Store: до 30.07 секретов не
было, а 0.2.2 залита в дашборд руками. Поэтому **первый же bump версии (0.2.3) —
это одновременно и проверка выкладки**, и относиться к нему надо соответственно:

Порядок именно такой — `upload-only` на текущем main бесполезен, он собрал бы ZIP
той же версии 0.2.2, а Store отклоняет неувеличенную версию:

1. Дождаться вердикта по 0.2.2. Пока товар на ревью, обновить пакет нельзя
   (`ITEM_NOT_UPDATABLE`).
2. Bump версии до 0.2.3 **в ветке, не в main**.
3. `Actions → Release → Run workflow`, выбрать эту ветку, режим **`upload-only`**.
   Соберётся ZIP 0.2.3 и ляжет в Store черновиком: без отправки на ревью и без
   GitHub Release с тегом (Release создаётся только с main или с тега).
4. В логе шага «Upload to Chrome Web Store» ждём `uploadState=SUCCEEDED`, в
   дашборде — что подтянулась именно 0.2.3. `invalid_grant` означает отозванный
   токен: скрипт печатает причину, порядок перевыпуска в docs.
5. Только после этого мержить ветку в main — дальше автоматика сама выпустит
   Release и отправит версию на ревью.

Заодно на живом прогоне проверить то, что мок покрыть не может: реальные коды
ответов v2 и что `publish` действительно отправляет на ревью, а не публикует молча.

### 0.3.x — надёжность

- Повторы с backoff при сетевых сбоях.
- `ETag` / `If-Modified-Since`, чтобы не тянуть неизменившийся фид.
- Гонять `tests/e2e-live.cjs` перед каждым релизом: нужен доступ к zakupki.gov.ru из РФ (прокси).
- Клик по системному уведомлению (`chrome.notifications.onClicked` → открытие вкладки) — единственный сценарий, который не автоматизируется: событие порождает сам браузер. Проверено косвенно: id уведомления равен ссылке на закупку.
- Проверка на самой старой поддерживаемой версии Chrome (119). Смоук-тест гоняется на текущем Chromium, где доступны и `getContexts`, и `hasDocument`; несовместимость с 119–149 поймал бы только запуск на старом билде.
- Различать ленты в уведомлениях. `channel/title` у ЕИС — «Результаты поиска в реестре заказов и закупок» для ЛЮБОГО поиска, поэтому fallback `feed.title || parsed.channelTitle` даёт одинаковую подпись всем безымянным лентам. Подставлять в неё `searchString` из URL ленты либо требовать название при добавлении.
